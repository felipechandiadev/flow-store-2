Sección 8 — Glosario de términos

Este glosario explica los conceptos más usados a lo largo del informe, en un lenguaje simple y orientado a negocio. La intención es que la lectura sea clara para un emprendedor o administrador que opera su comercio día a día, sin requerir conocimientos técnicos.

8.1 Términos de operación (día a día)

POS (punto de venta)

La aplicación usada en caja para buscar productos, armar la venta, cobrar e imprimir el comprobante. También suele registrar la sesión de caja y sus cierres.

Panel de administración (Admin)

La aplicación de “oficina” donde se configura el sistema y se controla la operación: catálogo, precios, usuarios/permisos, existencias, reportes y trazabilidad.

Catálogo

Conjunto de productos/servicios cargados en el sistema con sus datos (nombre, códigos, marca, precios, impuestos y categorías).

Inventario / Stock / Existencias

Las unidades disponibles de un producto. El sistema permite consultar saldos y registrar movimientos (ventas, compras, ajustes o traslados según configuración).

SKU

Código interno para identificar un producto o variante. Ayuda a ordenar y buscar, y suele ser distinto al código de barras.

Código de barras

Código impreso en el producto, diseñado para lectura con lector/escáner. Se usa para acelerar la búsqueda en caja.

Lista de precios

Conjunto de precios aplicables en un contexto (por ejemplo, por punto de venta, tipo de cliente o canal). Permite que el POS cobre con precios consistentes según la regla definida.

Sesión de caja

Periodo de operación de una caja (turno). Se asocia a aperturas, ventas registradas, movimientos de efectivo y cierre.

Arqueo

Revisión del efectivo y medios de pago en caja para comparar lo que “debería haber” según el sistema versus lo que existe en la caja.

Cierre de caja

Proceso de término de una sesión de caja. Resume ventas y permite dejar registrada la situación final para control del negocio.

8.2 Términos tributarios y documentos (Chile)

SII

Servicio de Impuestos Internos de Chile. Define normativa y sistemas para documentos tributarios electrónicos.

DTE

Documento Tributario Electrónico. Es el nombre general para boletas, facturas y otros documentos emitidos electrónicamente.

Boleta electrónica

Documento tributario asociado a una venta al consumidor final, emitido electrónicamente según normativa del SII.

Factura electrónica

Documento tributario usado en ventas a empresas u operaciones que requieren facturación, emitido electrónicamente.

Nota de crédito

Documento usado para corregir o revertir total o parcialmente una operación previa (por ejemplo, devolución o corrección de monto), según corresponda.

Excedentes de DTE

Cobros adicionales cuando se supera la cantidad de documentos incluidos en un plan (por ejemplo, si el plan incluye 1.000 DTE y el negocio emite más en el mes).

8.3 Términos de costos y modelo de cobro

TCO (Total Cost of Ownership)

Costo total de propiedad: lo que cuesta operar una solución en un horizonte de tiempo (en este informe, 24 meses), sumando licencia o suscripción, implementación, excedentes y costos variables como comisiones.

UF

Unidad de Fomento. Se usa en Chile para fijar precios que se ajustan con inflación. Cuando un plan se cobra en UF, su valor en CLP cambia con el valor de la UF.

Suscripción

Pago recurrente (mensual o anual) para usar el software y/o sus servicios asociados.

Modelo modular

Esquema donde se paga por módulos o funciones (por ejemplo: boleta, POS, inventario, usuarios). Permite partir con poco y sumar según necesidad.

Operador de pagos

Empresa o servicio que procesa pagos con tarjeta y cobra una comisión por transacción. En algunos modelos, el cobro con tarjeta puede representar una parte importante del costo total.

Comisión por transacción

Porcentaje (o esquema mixto) aplicado sobre las ventas cobradas con tarjeta u otros medios, que se paga al operador de pagos o al proveedor según el modelo.

8.4 Términos técnicos

Cloud (nube)

Infraestructura en internet donde se aloja el sistema (servidor y base de datos), permitiendo acceso desde el local sin depender de un computador específico.

Servidor

Computador (normalmente en la nube) donde “corre” el sistema y se procesan las operaciones.

Hosting / Alojamiento

Servicio que provee la infraestructura para mantener el sistema disponible en internet.

Backend (API)

Parte “invisible” del sistema que procesa la información y aplica reglas de negocio (por ejemplo, registrar una venta o mover stock). La API es la forma en que las aplicaciones (POS y Admin) se comunican con esa parte.

Base de datos

Lugar donde se guarda la información del negocio (productos, ventas, clientes, movimientos y reportes).

Respaldo (backup)

Copia de seguridad automática de la información para poder recuperarla ante errores o incidentes.

Restauración

Proceso de recuperar la información a partir de un respaldo (por ejemplo, volver a un estado anterior).

Dominio

Dirección de acceso al sistema (por ejemplo, un nombre web). Permite entrar al POS o al panel usando una URL estable.

URL

Enlace o dirección completa de acceso (por ejemplo, https:// + el dominio).

Subdominio

Variación del dominio que apunta a una parte específica (por ejemplo, pos o admin antes del dominio).

DNS

Configuración que hace que un dominio o subdominio apunte al servidor correcto.

HTTPS / certificado

Configuración de seguridad que cifra la conexión entre el navegador y el sistema, evitando advertencias y protegiendo la información en tránsito.

SSL/TLS

Tecnología detrás de los certificados de seguridad: habilita el cifrado usado por HTTPS.

PWA

“Aplicación web progresiva”: una app que corre en el navegador, pero puede instalarse y usarse como si fuera una aplicación (por ejemplo, en un PC de caja), manteniendo una experiencia ágil.

Navegador

Programa con el que se accede al sistema (por ejemplo Chrome o Edge). Ahí se ejecutan el POS y el panel.

Credenciales

Usuario y contraseña. Sirven para ingresar al sistema y asociar acciones a un responsable.

Autenticación / inicio de sesión

Proceso de validar las credenciales para permitir el acceso según rol y permisos.

Roles y permisos

Reglas de acceso que determinan qué puede ver o hacer cada usuario (por ejemplo, ver costos, anular ventas o cerrar caja).

Despliegue (puesta en producción)

Trabajo de dejar el sistema operativo en el servidor cloud: subir y configurar servicios, verificar funcionamiento y habilitar el acceso para uso real.

Pruebas de humo

Verificación rápida tras un despliegue para confirmar que lo esencial funciona (por ejemplo: login, ventas, consultas básicas).

Implementación / parametrización

Configuración funcional del sistema para el negocio: reglas, permisos, estructura y criterios de aceptación para operar.

Migración / carga inicial

Proceso de llevar datos existentes (catálogo y stock) al sistema, idealmente mediante carga masiva y validación.

Integración

Conexión entre el sistema y otros servicios o dispositivos (por ejemplo, operador de pagos, impresora o lector).

Sincronización

Que la información se mantenga consistente entre el POS, el panel y la base de datos (por ejemplo, venta que descuenta stock).

Disponibilidad (uptime)

Medida de cuánto tiempo el sistema está accesible y funcionando correctamente.

Latencia

“Demora” percibida al usar el sistema; depende de internet, del servidor y de la carga del servicio.

Actualización

Nueva versión del sistema con mejoras o correcciones. Puede requerir trabajo de implementación para aplicarla.

Go-live / puesta en marcha

Inicio de operación real: momento en que el sistema comienza a registrar ventas oficiales en el local.
